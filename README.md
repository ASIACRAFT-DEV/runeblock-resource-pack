# RuneBlock resource pack

Resource pack for the RuneBlock MMO server (Minecraft **1.21.11**, resource pack format **75**).

- `pack/` is the pack root (`pack.mcmeta` + `assets/`). Custom content goes under `assets/runeblock/`.
- The server sends the pack **after** a player joins, never during login (a pack in the login phase caused
  mass join timeouts on another server of ours).

## Releasing
1. Commit the changes, then tag and push: `git tag v0.1.0 && git push origin v0.1.0`
2. The `release` workflow zips `pack/` and publishes a GitHub release whose notes give the **URL** and **SHA-1**.
3. Point the server at that URL + SHA-1, then confirm in game that the pack downloads.

Releases are immutable: never replace a released zip in place. Players' clients cache by SHA-1, so ship a new tag instead.

## Gear models (v0.4.0)
3D weapon models for ArcaneSouls gear (0.18.0+: a `model: "runeblock:<name>"` key on a `gear.yml` item sets the item's `item_model`).
- `pack/assets/runeblock/items/<name>.json` = the item definition the server names; it points at `models/item/gear/<name>.json`,
  whose textures are in `textures/item/gear/<line>/`. Bows and crossbows use the same pull / charge states as the vanilla definitions.
- Two lines, 12 models each: sword, greatsword, axe, hammer, mace, scythe, spear, staff, trident, harp, bow, crossbow.
  **Sunforged** (gold glow) and **Rimeforged** (ice).
- All of it is generated by `tools/import_gear_models.py <extracted asc-ranks-pack>/assets pack/assets` from the SolForge (`nexusset`)
  and Arctis (`winterset`) sets of asc-ranks-pack v1.18.38, made by PolygonMC. Rimeforged uses the Arctis model where there is one
  (sword, axe, bow, crossbow) and otherwise the SolForge model with its glow colours swapped for the Arctis ice palette
  (textures named `n_*`). `harp` is the bow model without pull states. Third-party art: check the licence covers this server before a release.
- A new weapon = one model + its textures + one `items/<name>.json`, then one row in `gear.yml`. Never seen in a client yet.

## Metal weapons, ingots and ores (v0.4.1, weapons redrawn in v0.4.2)
All written by `tools/gen_metal_weapons.py <1.21.11 client jar> pack/assets` (for ArcaneSouls 0.19.0):
- 146 flat 32 px weapon sprites of our own: 14 weapon types in 10 metals (`runeblock:<metal>_<type>`), plus a sword and an axe
  in Mithril, Bloodiron and Voidsteel. Drawn by `tools/weapon_art.py` from shaded parts (one function per weapon type), with three
  looks by gear tier: Novice plain, Artisan trimmed, Mythic with gems and a glowing edge in the metal's accent colour.
- Held models (v0.4.3, `tools/held_models.py`): the item definitions of `<metal>_gauntlet` and `<metal>_grimoire` switch on
  `minecraft:display_context`: the flat sprite in the GUI, on the ground and in item frames; in a hand a 3D model. Gauntlet = a plated
  glove around the fist and forearm (ArcaneSouls 0.20.0 puts a twin in the off-hand, so both arms); grimoire = an open book whose
  `<metal>_grimoire_pages.png` is animated (8 frames page turn + 16 frames rune pulse, frametime 2). Display transforms are first guesses.
- 3 ingots and 3 ores (recoloured vanilla ingot / deepslate gold, iron and emerald ore textures; Mithril moved off the diamond look in v0.6.4).
- `assets/minecraft/blockstates/note_block.json`: the ore BLOCKS in the world are note block states
  (`instrument=custom_head`, note 1 = Mithril, 2 = Bloodiron, 3 = Voidsteel); every other note block state keeps the vanilla model.
  A new Minecraft version with a new note block instrument needs that instrument added to the script's list.

## Boss models
For now the two story bosses use vanilla mob bodies (wither, warden), so they need nothing from this pack.
Blockbench models for them go here later (they are built by the server's model plugin into its own zip, then merged in).

## Bottom HUD (BetterHud, v0.3.2)
HP (red) and mana (blue) bars over a reskinned hotbar, drawn by the **BetterHud** plugin (1.14.1 on the box; 2.x needs Java 25).
The vanilla hearts, drumsticks and armour are blanked here; crosshair, XP bar, air and mount hearts stay.
- `tools/gen_hud.py` draws the pictures: hotbar sprites into `pack/`, bar pictures into `betterhud/assets/`
- `betterhud/` mirrors the box's `plugins/BetterHud/` (images, layouts, huds, texts, shader.yml). Upload it, run
  `hud reload` in the **panel console** (RCON can't run it), fetch `plugins/BetterHud/build.zip`, then
  `tools/merge-betterhud.sh build.zip`. The merged files must match the box's config exactly, so always re-merge after a change
- BetterHud gotchas (1.14.1, seen in game): text glyphs are built at 16 px, so layout text `scale: 0.5` = vanilla size; `/` in a `pattern` escapes the next char (write `//`); each layout draws shifted left by ~half its width, so `huds/` pixel x = wanted left edge + half the bar width
- `shader.yml` `bar-color: pink`: BetterHud blanks that boss bar colour for its own carrier bar. Never yellow (ArcaneSouls cast bar, tracker, escort HP)

## Mockup HUD M1 (v0.8.0, ArcaneSouls 0.44.0)
HP / MP panels, level shield, EXP bar and the hotbar ring of the approved mockup art (`art/mockup-hud/`, drawn by
`tools/gen_mockup_hud.py`, spots in its `layout.json`). `python3 -I tools/gen_hud_m1.py` writes `betterhud/{images,layouts,huds}/runeblock_m1.yml`
+ `betterhud/assets/rb_m1_*.png`; `tools/gen_hud.py` copies the art hotbar into the vanilla sprites.
- The layout is gated on `%arcane_packhud%` = true (ArcaneSouls `hud.layout: pack` AND the player's pack loaded); the v0.3.x bars
  (`runeblock.yml`) are gated on the opposite, so each player sees one. `betterhud/config.yml` = the box file + `runeblock_m1` in `default-hud`.
- The hotbar sprites are vanilla, so every player with this pack gets the new hotbar whatever `hud.layout` says. The vanilla XP bar and
  level number are NOT blanked here (a pack can't do it per player): ArcaneSouls empties them for pack-layout players; `disable-level-text` stays false.
- `offset: left` on the layout (BetterHud 1.14.1 sources): x = left edge, no half-width shift. BetterHud trims transparent borders and adds
  back only the left trim, so the generator adds a picture's empty top rows to its y.
- `hud reload` works from the panel/server console only: over RCON it does nothing (no log line, build.zip not rebuilt; checked on a local
  1.14.1 server 2026-11-06). build.zip is only rewritten when the pack content changes (a text colour change doesn't).
- Check without a client: `python3 -I tools/composite_betterhud.py --build build.zip --out <dir>` places the generated pictures at the y
  decoded from the generated font ascents over the GUI-3 shot and compares them with `layout.json`.

## Mockup HUD M2 (v0.8.1, ArcaneSouls 0.45.0)
The skill row above the HP / MP panels: 4 slots (slot 4 = ultimate, gold frame + flames), the bound skill's icon, today's
click combo in a badge, a clock-sweep cooldown with whole seconds, and a no-mana look (grey icon + veil). `python3 -I
tools/gen_hud_m2.py` writes `betterhud/{images,layouts,huds}/runeblock_m2.yml`, `betterhud/assets/rb_m2/` and
`betterhud/skill_icons.txt`; `runeblock_m2` is in `betterhud/config.yml` default-hud. Same gate as M1 (`%arcane_packhud%`).
- Every changing picture is ONE `sequence` image picked by a listener (no per-skill conditions): BetterHud puts an empty
  frame first when an image has a listener, so value k / max with max = number of files shows file k, 0 shows nothing.
  Icon = 88 icons + 88 no-mana copies, value `%arcane_skill_<n>_icon%`; sweep = 16 frames, `%arcane_skill_<n>_cdpct%`
  (0-100); badge = [combo, bow-mirrored combo], `%arcane_skill_<n>_badge%`; seconds = text `[papi:arcane_skill_<n>_cd]`
  drawn while it isn't '0'. Same texture + y + scale = one shared glyph for all four slots (205 glyphs in all).
- `skill_icons.txt` is the frame order and is **append-only**: ArcaneSouls maps a skill id to its line (jar resource
  `pack-skill-icons.txt`, or `plugins/ArcaneSouls/pack-skill-icons.txt` if present). A new icon goes at the end; copy the
  file to the box (or ship a jar) with the pack that adds it. A skill with no line shows an empty slot (boot line lists them).
- Icons are the 64 px pack icons at layout `scale: 0.25` (16 GUI px, full detail at GUI 3/4). A sequence trims only empty
  columns and shifts by trim x scale (rounded), so the generator gives column 0 and 63 one alpha-1 pixel: nothing is trimmed.
- M1 fixes in the same version: HP numbers red (#FF5A4A) at <= 30 % (two text elements on BetterHud's `health_percentage`);
  EXP progress ticks moved from the fill into the frame rim (the centred EXP text crossed them).
- `tools/composite_betterhud.py` draws M1 + M2 (sequences, scaled glyphs, text conditions) for the states ready / cooldown /
  nomana / empty / lowhp (`--set m2`). `MMO/tools/hudm2.js` reads the boss-bar glyphs a bot receives and maps them through
  the build's font, so it checks which icon / sweep / badge BetterHud actually picked.

## Skill objects (v0.6.9)
3D objects that fly in skills, for ArcaneSouls 0.35.0 (`fx: object`, `rbtelegraph{…;obj=…}`, `rbobject{}`), written by
`python3 -I tools/skill_objects.py [--preview out.png]` (the preview is a headless ray cast, no client):
`runeblock:skill_object/<name>` for searing_lance, infernal_meteor, tidal_wave, ice_spear, spectral_blade, boulder,
veil_lance, spirit_arrow; textures in `textures/item/skill_object/` (`water.png` is animated).
- Every model is centred on (8, 8, 8) with its front toward NORTH (-z): the item display renderer turns items 180° about y,
  so ArcaneSouls rotates the display's +z onto the flight. Shown with display context `none` (16 px = 1 block at scale 1).
- 1.21.11 element rotations take any angle (`axis`+`angle`), and `light_emission` makes the fire/void/spirit parts glow.
- Never seen in a client yet: if they fly backwards, set ArcaneSouls `vfx.objects.model-front: south` (no pack change).

## Rank icons (v0.7.0)
11 rank icons as characters of the `minecraft:default` font, so they show in chat, TAB and any text:
U+E100 Owner · E101 Grand Master · E102 Game Master · E103 Moderator · E104 Helper · E105 Knight · E106 Hero ·
E107 Champion · E108 Divine · E109 Immortal · E10A Adventurer. 16 px textures in `textures/font/rank/`, drawn 8 units
high (one chat line), so they are sharp at GUI scale 2. Written by `python3 -I tools/rank_glyphs.py <MMO/rank-icons> pack/assets`
(icons drawn by `MMO/tools/rank_icons.py`). Glyphs take the text colour, so a prefix must put `&f` before the character.
Fonts from packs stack, so this file only adds these characters to the vanilla font.

## World map tiles (v0.7.1)
The picture behind the client mod's world map (asc-mmo-gui 0.2.5 `MapScreen`, data from the WorldMap plugin):
`textures/map/t_<tx>_<tz>.png`, 512 px tiles at 2 blocks per pixel, tile (0, 0) = blocks 0..1023 × 0..1023, ungenerated land
transparent, colours quantised to 256. 34 tiles for NEPTAR (`tiles.json` lists them; the WorldMap config carries the same list).
Written by `python3 -I MMO/tools/map_tiles.py <box world/region dir> <1.21.11 client jar> pack/assets` from the box's region
files; re-run it when the world changes enough to matter, then release a new pack version.
